# Container setup (generic)

This Compose example adds one Yoto service to an existing trusted internal Docker network. It publishes **no host port**. Adapt paths, network, UID/GID and ACLs to your host; never replace unrelated services in an existing stack.

1. Register your own Yoto public OAuth client with redirect URI `http://127.0.0.1:8787/callback`. On a computer where your browser and callback listener share loopback, run the stdio MCP and call a read tool once to complete supervised consent. Stop that process; securely copy the resulting `0600` OAuth session file into the host's private `session/oauth-session.json`. Do not use a login URL from a remote container console: its callback points at *the browser's* loopback, not the container's. There is no password automation.
2. Create `session/`, `jobs/`, `uploads/` inside a dedicated `YOTO_DATA_ROOT` with private permissions; configure your filesystem ACLs so container UID/GID **10001:10001** can traverse/write them. Copy a completed job journal if migrating from another instance. **Do not run both instances against independently copied rotating refresh tokens**; stop the old writer before migration. Inspect any pending jobs first—absolute staging paths may need separate recovery. The session directory must remain writable for atomic refresh rotation. Recheck `0600` on the session file after a copy if ACLs remap modes.
3. Add only the Yoto service from [`compose.yaml`](compose.yaml) to your existing stack. In the stack's protected `.env`, set `YOTO_DATA_ROOT`, `MCP_NETWORK` (the name of your existing private Docker network), `YOTO_CLIENT_ID`, and a unique random `YOTO_HTTP_TOKEN` (for example, a locally generated 32-byte hex token). `ACOUSTID_API_KEY` is optional. Never commit or print token values. Keep `YOTO_ALLOW_WRITES=0` at first. Ensure the external network exists before deploying; this example has no callback-port mapping and does not expose port 8000 to LAN/Internet.
4. Check `http://yoto-mcp:8000/healthz` from the private network, confirm `/mcp` rejects a missing/wrong bearer, then initialize the Streamable HTTP MCP client at `http://yoto-mcp:8000/mcp` with an `Authorization` header whose value is `Bearer ` followed by your secret HTTP token. Call `list_playlists` and verify a read. Probe each mount as UID 10001 (create, stat, remove a disposable file) before considering writes. Only then enable the write gate as an intentional separate change; mutation tools still default to dry run. Avoid simultaneous writers on a card because the upstream whole-card write has no CAS.
5. Remote MP3 uploads need no extra port: `create_mp3_upload` returns a single-use `http://yoto-mcp:8000/uploads/<secret>` link. The shell running `curl -T` must reach `yoto-mcp:8000` the same way the MCP client does. A reverse proxy in front must pass `PUT`/`POST` bodies up to 100 MiB on `/uploads/`.

The initial GHCR package is private by default even for a public source repo. After the first reviewed image is pushed, its owner sets **Package settings → Change visibility → Public** in GitHub and reruns the publish workflow. This change is irreversible. CI must successfully verify an **anonymous** manifest request for both `latest` and `sha-<commit>` tags before unauthenticated deployment. To roll back, pin the last verified `sha-<commit>` image tag; preserve all state mounts.
